## 先选择运行方式

### 方式一：直接用 Google Chrome 打开 index.html（离线）

下载并解压完整项目，双击 `index.html`，或在 Chrome 中打开该文件。无需安装依赖。可以使用原有功能和日期筛选；启事保存在当前浏览器，**公共评论此时未连接，不会假装多人共享**。原有 `campus-light-items-v1` 和 `campus-light-owner-v1` 数据继续读取，升级不需要清空浏览器数据。

请保留原来的文件路径与浏览器配置。浏览器对 `file://` 本地存储的具体处理可能随路径变化；将项目移动到新目录不等于旧浏览器数据自动转移。不要删除旧文件夹或清除旧数据。

### 方式二：启用共享启事与评论（本机验收）

安装 **Node.js 22.13+，建议 24 LTS**，在 Windows CMD 中运行：

```bat
cd /d D:\codex\校园拾光_协作开发
node server\server.js
```

服务运行不需要 `npm install` 或第三方服务账号。在 Chrome 打开 `http://127.0.0.1:8787`，页面自动连接同源共享服务。也可继续双击 `index.html`，在页面顶部展开“共享服务设置”，填写 `http://127.0.0.1:8787`，点击“保存并连接”。保持这个服务窗口运行。

另开一个 Chrome 无痕窗口访问同一服务，在会话 A 发布启事，复制启事链接，在会话 B 打开并评论；A 点击“刷新评论”即可看到 B 的线索，反向同样可用。自动刷新间隔为 15 秒。测试时使用虚构联系方式与独立测试物品。

**localhost / 127.0.0.1 只代表当前电脑，不能用这个地址让另一台设备连接。** 本次已验证两套独立 Chrome 会话连接本机服务互相读写，尚未部署公共 HTTPS 服务、尚未进行两台真实设备访问验证。

### 方式三：不同设备访问同一个 HTTPS 服务

账号持有人准备可运行 Node.js 的服务器或容器平台、一个 HTTPS 地址及持久磁盘。GitHub Pages 只能托管静态前端，不能运行本项目的共享服务。

1. 上传项目代码，安装 Node.js 22.13+；共享服务无需安装生产依赖。
2. 持久磁盘示例挂载为 `/var/lib/campus-light`，设置服务环境变量：

```text
HOST=0.0.0.0
PORT=8787
DATA_FILE=/var/lib/campus-light/campus.sqlite
ALLOWED_ORIGINS=null,https://campus-light.example.edu
```

`example.edu` 是占位地址，必须替换成实际前端来源，多个来源用英文逗号分隔，精确填写协议、域名和端口，不加路径或结尾斜杠。`null` 是 Chrome 直接打开本地 HTML 时的来源；如不允许本地文件联网，可从允许列表移除。

3. 启动命令 `node server/server.js`，由平台提供 HTTPS，或用反向代理将 HTTPS 请求转到 8787。例如 Nginx 的站点配置（需填入已签发的证书路径）：

```nginx
server {
    listen 443 ssl;
    server_name campus-light.example.edu;
    ssl_certificate /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;
    client_max_body_size 1m;
    location / {
        proxy_pass http://127.0.0.1:8787;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

4. 同一服务也提供 `index.html`、`js/`、`css/`、`assets/`。所有人打开同一个 `https://实际域名/`；可复制带 `#post/稳定ID` 的链接直接打开同一启事。
5. 如果前端单独托管，或测试人员下载 HTML，在顶部填写同一服务的 **HTTPS 根地址**。也可在 `js/config.js` 设置 `window.CampusConfig = { apiUrl: 'https://实际域名' };`。网页保存的服务地址优先于该模板；留空并保存可回到离线模式。
6. 公网启用前，用两台设备发布、留言、刷新，验证同一启事、图片、评论及权限。当前没有公网部署地址，不能将本机验收描述为已上线。

前端只配置公开地址。证书私钥、云平台凭据、数据库与匿名会话令牌不得提交到 Git。SQLite 文件位于持久磁盘，关闭服务后复制数据库备份；不要删除运行中的 WAL 文件。部署平台必须保存磁盘，否则重建服务会丢失共享数据和身份权限。

## 日期筛选与评论使用方法

- 广场的“丢失 / 拾取日期”是启事中的物品日期，**不是发布时间**。开始、结束两端均包含当天；仅开始表示当天及之后，仅结束表示当天及之前；都为空表示不限制。
- 日期可与关键词、寻物/招领、类别、状态共同使用。开始晚于结束会显示提示、保留输入、隐藏结果。清除筛选同时清空全部条件，无结果时也有清除入口。
- 详情下方“评论与线索”展示当前启事状态、昵称、正文和本地时区下的发表时间，按服务端时间从早到晚，同一时间按写入顺序排列。已完成启事仍能阅读和补充线索。
- 昵称 2～24 个字符，正文 1～500 个字符，前后空白在提交前去掉。提交时按钮禁用；失败保留输入，可重试；成功清空正文。相同请求的重试由服务端去重。
- 评论通过 `textContent` 作为普通文本展示；请通过物品特征核实线索，避免公开完整证件号码、住址等信息。
- 原有最多 3 张 JPG / PNG / WebP 照片，每张原图不超过 5 MB，浏览器压缩到最长边 1280 像素、每张不超过 200 KB；用户照片优先，演示启事保留对应写实图片。

## 数据保存与权限规则

| 数据 | 本地模式 | 共享模式 |
| --- | --- | --- |
| 启事和压缩照片 | 原来的 localStorage 键 | 服务端 SQLite `items` 表，所有用户读取同一份 |
| 评论 | 不提供本地冒充公共评论 | SQLite `comments` 表，关联稳定启事 ID |
| 发布者身份 | 原浏览器本地演示标识 | 服务端签发 256 位随机令牌；数据库仅存 SHA-256 摘要 |
| 网页配置 | `campus-light-api-url` 保存公开根地址 | 同左 |
| 权限令牌 | 无 | `campus-light-session:服务根地址` 保存在浏览器，按服务隔离 |

服务端的 `sessions(owner, token_hash)`、`items(id, owner, legacy_key, data)`、`comments(id, item_id, owner, request_id, nickname, body, created_at)` 三张表在首次启动时自动建立。`items.data` 是启事字段与压缩图片数组的 JSON；`legacy_key` 只用于复制旧启事的去重。

| 接口 | 权限和效果 |
| --- | --- |
| `POST /api/session` | 首次签发匿名令牌；已有 Bearer 令牌时校验并复用身份 |
| `GET /api/items` | 公共读取启事；启事 ID 为服务端 UUID，示例 ID 固定 |
| `POST /api/items` | 必须有有效令牌，服务端绑定发布者，忽略前端传入 ownerId |
| `PATCH /api/items/:id` | 仅令牌对应发布者可修改 active / resolved 状态 |
| `DELETE /api/items/:id` | 仅发布者可删除；数据库外键同时删除该启事评论 |
| `GET /api/items/:id/comments` | 只读该启事评论 |
| `POST /api/items/:id/comments` | 必须有有效令牌；服务端校验长度，以发布者令牌及 requestId 去重 |

读取是公开的，知道 URL 的人可以看到启事、联系方式、照片与评论。前端只显示自己的维护入口，真正的写入权限由服务端校验，伪造 ownerId 或其他用户 UUID 不会获得修改权。请求体上限 1 MiB，并有每分钟限流。静态文件采用白名单，数据库、服务端源码、环境文件不提供下载。

匿名身份不是实名认证。保留本浏览器的令牌才可以维护自己的共享启事；目前没有跨设备身份登录或找回机制。令牌不是可公开的分享信息。

### 旧数据升级

离线模式保持原数据、照片、状态与权限。连接共享服务后显示该服务的广场；点击“复制我的旧启事到共享广场”可把当前浏览器旧身份的启事创建为该服务匿名身份的新发布，原件不变，状态和照片保留。同一身份重复复制相同旧 ID 不会重复添加。

旧 ownerId 是客户端标识，无法证明真实身份，所以**不会用旧 ownerId 接管已有共享记录，也不会自动上传旧联系方式和图片**。这是显式复制，不是对旧数据所有权的服务端认证。
