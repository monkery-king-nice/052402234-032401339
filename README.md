# 校园拾光｜校园失物招领

基于第一次结对作业的“校园拾光”原型，完成「发布信息 → 浏览或搜索 → 查看详情 → 联系发布者 → 更新状态」流程。结对成员：**052402234 郭泽强**、**032401339 沈冠宇**。

## 运行方法

1. 下载整个项目文件夹，保持下方目录结构不变。
2. 在 **Google Chrome** 中打开 `index.html`。无需安装依赖、启动服务器或联网。
3. 首页有 6 条标明演示用途的示例信息，可直接体验搜索、分类与状态筛选、查看详情、复制联系方式。
4. 点击「发布信息」填写寻物或招领表单。发布成功后自动进入「我的发布」。打开自己发布的信息，点击「标记为已找到 / 已归还」。若误操作，可恢复为进行中。
5. 刷新网页，自己发布的信息仍保存在当前浏览器。Chrome 清除该页面的本地数据后，发布记录会消失。

## 功能与操作

| 功能 | 操作 |
| --- | --- |
| 浏览信息 | 首页直接展示最新寻物和招领信息，卡片标明类别、地点、日期、状态。 |
| 搜索和筛选 | 搜索框可搜物品名称、地点、类别、描述；信息类型、类别、状态可组合筛选。无结果时有明确提示。 |
| 发布信息 | 选择寻物/招领并填写名称、类别、地点、日期、描述、称呼和联系方式。缺失或格式不正确时显示对应错误。 |
| 查看详情与联系 | 点击卡片「查看详情」，可阅读完整线索并复制发布者留下的联系方式；请先核实物品特征再交接。 |
| 维护状态 | 进入「我的发布」→ 打开自己发布的信息 → 标记为「已找到」或「已归还」；支持恢复。首页和详情同步显示最新状态。 |
| 快捷操作 | 键盘按 `/` 聚焦搜索框；移动端底部导航便于单手操作。 |

## 测试

安装 Node.js 18+ 后，在项目根目录运行：

```bash
node --test tests/model.test.js
```

测试使用 Node.js 内置 `node:test` 和 `node:assert/strict`，无需安装第三方包。目前有 **18 个**测试，覆盖有效发布、多个非法输入分支、关键词与组合筛选、排序、发布者权限、状态转换、持久化与损坏数据回退。单元测试文件可保留在仓库中，也可按照课程要求在提交前自行移除；推荐保留，便于复核。

### 手动走查建议

1. 搜索「校园卡」，检查仅出现相关信息；再搜索随机字符串，检查无结果提示。
2. 切换寻物/招领、类别和状态；清除筛选后检查全部记录恢复。
3. 打开一个演示卡片，检查详情与联系方式；用复制按钮核对剪贴板内容。
4. 尝试提交空表单或过短描述，检查错误提示；填写有效信息发布。
5. 在「我的发布」标记完成，回到首页查看状态；刷新页面确认状态保留，再恢复状态。
6. 缩窄窗口，检查移动端布局与底部导航。

## 数据与实现边界

本版是可直接打开的静态 Web 程序，使用浏览器 `localStorage` 保存发布信息与当前浏览器的发布者标识。它不连接服务器，所以**不同设备或浏览器之间不会自动同步信息**。示例信息与联系方式均为演示数据，不代表真实失物或可联系的人。状态维护仅允许当前浏览器修改其创建的信息；这是一种本地演示权限，不能替代正式产品的账号认证。

代码在显示用户输入前进行 HTML 转义，避免直接将输入作为 HTML 注入。正式部署到校园范围使用时，应添加服务端存储、鉴权、内容审核和真实的联系方式保护机制。
