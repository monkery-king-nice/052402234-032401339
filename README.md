# 校园拾光｜校园失物招领

结对成员：**052402234 郭泽强**、**032401339 沈冠宇**。

本项目采用 HTML、CSS 和 JavaScript。本次最终方案是**纯前端本地使用**：用 Google Chrome 直接打开 `index.html`，即可使用日期筛选、评论、照片上传、发布与维护等全部页面功能。无需本地共享程序、后端接口或部署平台。

## 下载与运行

1. 下载仓库 ZIP 并解压完整项目，保持 `index.html`、`css/`、`js/`、`assets/` 的相对位置。
2. 在 Google Chrome 中按 `Ctrl+O` 选择 `index.html`，或把文件拖入 Chrome。
3. 浏览“失物招领广场”，点击卡片查看详情与“评论与线索”，或通过“发布启事”填写内容并上传照片。

日常使用不需要 Node.js、安装依赖或联网。Node.js 和开发依赖仅用于自动化验收。

升级继续读取 `campus-light-items-v1` 和 `campus-light-owner-v1`，保留原有启事、压缩照片、状态和发布者标识，**无需清空浏览器数据**。尽量保留原文件路径和 Chrome 用户配置：`file://` 页面的存储范围可能随路径变化，移动项目不会自动迁移旧路径的浏览器数据。

## 日期筛选

筛选依据为启事填写的**“丢失 / 拾取日期”**，不是发布时间。

| 输入情况 | 结果 |
| --- | --- |
| 仅开始日期 | 开始当天及之后 |
| 仅结束日期 | 结束当天及之前 |
| 两者均填写 | 包含开始、结束当天 |
| 两者均为空 | 不限制日期 |
| 开始晚于结束 | 提示错误、保留输入，暂不展示结果 |

日期可与关键词、寻物 / 招领类型、类别、状态共同使用。“清除筛选”同步清空所有条件，无匹配时也提供清除入口。有效的 `YYYY-MM-DD` 日历字符串直接比较，避免时区转换导致一天偏差。

## 评论与线索

在详情下方填写昵称与正文，再点击“发表评论”。昵称为 2～24 个字符，正文为 1～500 个字符，提交前去除首尾空白。空白和超长输入显示字段提示。保存中禁用按钮；成功后更新列表、清空正文；失败保留输入并提示原因。

评论展示昵称、正文和发表时间，按时间从早到晚排序，同一时间保持插入顺序。无评论有引导文字。已完成启事仍可查看评论，并显示当前状态。

**评论仅保存在当前浏览器的 `localStorage`。刷新后保留，每条启事的评论独立。不同浏览器、Chrome 用户配置、无痕会话或设备之间不会同步启事和评论。本地留言不具备多人共享的公共评论能力。**

评论通过 `textContent` 作为普通文字展示，用户输入不会作为 HTML 执行。请依据物品特征核实线索，避免公开完整证件号码、住址等信息。

## 原有功能与数据

保留发布、搜索、详情、联系方式复制、“我的发布”、状态更新 / 恢复、照片上传 / 预览 / 压缩与二次确认删除。最多上传 3 张 JPG / PNG / WebP 照片，原图每张不超过 5 MB；压缩到最长边 1280 像素、每张不超过 200 KB。用户照片优先，六张对应物品的写实示例图片保留。

| 数据 | 保存位置 |
| --- | --- |
| 启事、状态、压缩照片 | `localStorage`：`campus-light-items-v1` |
| 当前浏览器发布者标识 | `localStorage`：`campus-light-owner-v1` |
| 每条启事评论 | `localStorage`：`campus-light-comments-v1:` 加 `encodeURIComponent(启事ID)` |
| 六张示例图片 | `assets/items/`，无需联网 |

每条评论包含 `id`、`itemId`、`nickname`、`body`、`createdAt`，每条启事独立保存评论数组。删除启事先保存启事列表，再清理目标评论键，不影响其他启事评论；清理失败有提示。损坏的评论记录显示错误，不自动覆盖旧记录。

本地发布者标识用于课程演示中的操作限制，**不是服务端身份认证**。有开发者工具和本地数据访问权的人能够修改记录。清除浏览器数据、删除用户配置或结束无痕会话会删除相应数据；浏览器容量有限，保存失败时需减少照片或检查存储权限。不要通过清空存储升级。

原共享程序数据库中的启事和评论不会自动迁入本地存储。本版读取原本的本地启事，不读取旧服务数据库。

## 自动化验收

仅测试需要 Node.js 20 或以上版本。项目目录中打开 Windows CMD，运行业务规则测试；使用内置测试工具，无需第三方依赖：

```bat
node --test tests/*.test.js
```

浏览器验收需要本机 Google Chrome 和锁定的开发依赖：

```bat
npm ci
npm run test:browser
```

浏览器测试直接打开 `file://` 的 `index.html`，使用独立 Chrome 上下文与测试数据，不启动共享程序，不读取或清空日常数据。覆盖日期边界与组合筛选、评论保存 / 隔离 / 校验 / 安全文字 / 保存失败、照片、发布者维护、删除和桌面 / 手机布局。截图输出到 `docs/screenshots/`，结构化结果输出到 `test-results/browser.json`。

**2026-10-10 实测：47 / 47 个业务规则测试、10 / 10 个 Google Chrome 页面场景通过。** Chrome 版本为 154.0.8037.93，测试关闭共享程序（8787 无服务监听），开启浏览器离线模式，直接打开 `index.html`，HTTP 请求为 0。照片发布、状态维护、删除、评论刷新保存及隔离均通过；320 / 390 / 768 像素视口已检查。

这是当前纯前端版本的独立结果。不同浏览器会话不共享评论已验证；没有进行公共共享验收，也不将本地留言描述为公共服务。已提交的测试记录见 `docs/browser-tests.json`（重新运行时输出到 `test-results/browser.json`），界面截图和细项见 `docs/本次改动博客素材.md`。

## 手动验收

1. 关闭旧共享程序，在 Chrome 直接打开 `index.html`，确认页面正常。
2. 使用独立测试启事检查日期当天边界、单侧 / 无日期、无效范围、组合条件、无结果与清除。
3. 在两条启事分别留言，刷新确认保留且隔离；检查空白、超长与 `<img src=x onerror=alert(1)>` 文字展示。
4. 发布测试照片并检查预览、详情和刷新保存；在“我的发布”更新 / 恢复状态，取消一次删除再确认删除。
5. 检查桌面、手机筛选区、弹窗滚动、评论输入和底部导航，没有遮挡主要操作。
6. 独立浏览器会话不应同步原会话启事或评论，这是本次预期行为。
